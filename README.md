# AI Interview System

A full-stack interview-preparation web application that helps candidates review their resumes, identify role-related skill gaps, practise interview questions, and receive structured feedback on their answers.

> **Current implementation note:** This repository is an early working prototype. Resume matching uses a built-in keyword list, interview questions come from a small predefined question bank, and answer evaluation uses a transparent rule-based scoring rubric. The current code does **not** call an external AI/LLM model. The project name describes its intended direction, not an AI capability currently implemented.

## Features

### Resume analysis
- Upload a resume in **PDF, DOCX, or TXT** format (maximum 5 MB).
- Extract readable text from the uploaded document.
- Detect skills using a predefined keyword list.
- Compare detected skills against a selected role:
  - Python Developer
  - Web Developer
  - Data Analyst
  - Machine Learning Engineer
  - General
- Display a role-match percentage, detected skills, matched skills, missing skills, and improvement suggestions.

### Mock interview
- Choose a role and request up to five practice questions.
- Questions are selected from a built-in question bank for Python, web development, data science, or general interviews.
- Submit answers one at a time and receive a score with basic feedback.

### History
- View recent resume analyses and answer evaluations during the current backend session.
- History is held in server memory and is cleared when the backend restarts.

## Getting Started

### Prerequisites

Install:
- Python 3.10 or newer
- Node.js (LTS recommended) and npm
- Git

### 1. Clone the repository

```bash
git clone https://github.com/vishalsharma8055/AI-Interview-System.git
cd AI-Interview-System
```

### 2. Start the backend

From the repository root:

**Windows PowerShell**
```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install fastapi "uvicorn[standard]" python-multipart python-docx pypdf
uvicorn main:app --reload
```

**macOS / Linux**
```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install fastapi "uvicorn[standard]" python-multipart python-docx pypdf
uvicorn main:app --reload
```

The API will be available at:
- API root: http://127.0.0.1:8000/
- Health check: http://127.0.0.1:8000/api/health
- Interactive API documentation: http://127.0.0.1:8000/docs

Keep this terminal running.

### 3. Start the frontend

Open a **second terminal** from the repository root:

```bash
cd frontend
npm install
npm run dev
```

Vite normally serves the app at http://localhost:5173. Open the URL printed in the terminal.

The frontend currently sends API requests to `http://127.0.0.1:8000`. Run the backend on that address and port for the default setup.

## API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/` | Backend welcome/status message |
| GET | `/api/health` | Health check |
| POST | `/api/analyze-resume` | Parse a resume and return keyword-based role matching |
| POST | `/api/questions` | Return role-based questions from the built-in question bank |
| POST | `/api/evaluate` | Score an answer using the demo rubric |
| GET | `/api/history` | Return recent in-memory activity |

### Example request: generate questions

```json
{
  "role": "Python Developer",
  "count": 5
}
```

### Example request: evaluate an answer

```json
{
  "question": "Explain exception handling in Python.",
  "answer": "I use try and except blocks to handle errors. For example, ..."
}
```

For exact request and response schemas, start the backend and visit http://127.0.0.1:8000/docs.

## Current Limitations

- Resume skill detection is keyword-based. It may miss skills expressed with different wording and does not understand context.
- The role-match percentage compares detected keywords with a small predefined checklist; it is not an ATS score.
- Interview questions are selected from a small static question bank, not generated by an LLM.
- Answer scores use answer length and basic structure signals. They do not verify technical correctness, communication quality, or factual accuracy.
- Activity history is stored in memory, is not tied to user accounts, and resets when the server restarts.
- No persistent database, authentication, or multi-user data separation is currently implemented.
- The backend CORS configuration currently allows the local Vite development origins listed in `backend/main.py`. Production deployment requires configuring the actual frontend origin and backend URL.

Use the results as practice guidance, not as a hiring decision or a substitute for human review.
